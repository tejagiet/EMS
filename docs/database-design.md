# Database Design Specification — EMS

**Project:** Employee Management System (EMS)  
**Institution:** GIET Polytechnic College | Artificial Intelligence (AI) Department | Batch 2024–2027  
**Team:** T-1 | **Publisher ID:** GIETP-AI-IT-EMS-T1-2026 | **Version:** 1.0.0

---

## 1. Database Architecture & Engine

- **Database Engine:** PostgreSQL 15.x hosted via Supabase.
- **Primary Key Standard:** UUIDv4 generated by `gen_random_uuid()` across all application tables.
- **Timestamp Standard:** All timestamps stored as `TIMESTAMPTZ` with defaults set to `NOW()`.
- **Auto-Update Trigger:** `set_updated_at()` trigger attached to all mutable tables updating `updated_at` automatically.

## 2. Table Inventory by Migration Phase

The EMS database schema is constructed across 8 progressive migrations in `supabase/migrations/`:

### Migration 1: `20261009000001_initial_schema.sql` (Foundations & Core)
1. `organizations`: Tenant metadata, code, slug, settings JSONB.
2. `branches`: Physical locations linked to an organization.
3. `departments`: Functional departments and sub-departments.
4. `designations`: Job titles, salary bands, and hierarchy levels (1–20).
5. `profiles`: User profile metadata mapping 1:1 to `auth.users.id`.
6. `employees`: Core employment records with employee code, department, branch, reporting manager.
7. `employee_history`: Immutable audit trail of employee record modifications.
8. `roles`: System-wide and organization-specific roles.
9. `permissions`: Granular permission registry with module and action codes.
10. `role_permissions`: Mapping table linking permissions to roles.
11. `user_roles`: Role assignments to user profiles with expiration support.
12. `settings`: Key-value configuration scoped by organization.

### Migration 2 & 3: `20261009000002_rls_policies.sql` & `20261009000003_auth_triggers.sql`
- Security Definer helper functions (`get_my_profile_id`, `get_my_organization_id`, `has_permission`, `is_org_member`).
- Row Level Security (RLS) enabled on all 12 core tables.
- Triggers: `handle_new_user()` auto-syncs `auth.users` to `public.profiles`.
- Boundary Triggers: `prevent_self_org_reassignment()` and `prevent_self_role_assignment()`.

### Migration 4: `20261009000004_attendance_shifts_leave.sql` (Attendance & Leave)
13. `shifts`: Work shifts with start/end time, grace period, and break duration.
14. `employee_shifts`: Shift assignments to employees with effective dates.
15. `attendance_records`: Daily clock-in/out records, total hours, and status.
16. `work_sessions`: Discrete work sessions within an attendance day.
17. `attendance_corrections`: Employee requests to rectify missed clocks.
18. `leave_types`: Configured leave categories (annual, sick, casual, etc.).
19. `leave_balances`: Annual quota balances per employee.
20. `leave_requests`: Leave applications, date ranges, and approval logs.

### Migration 5: `20261009000005_payroll_module.sql` (Payroll Engine)
21. `salary_structures`: Base salary rules per designation/grade.
22. `salary_components`: Detailed allowances and deductions.
23. `employee_salaries`: Active salary assignments to employees.
24. `payroll_periods`: Monthly and bi-weekly fiscal periods.
25. `payroll_runs`: Organization payroll runs with workflow status (`draft`, `review`, `approved`, `paid`).
26. `payroll_records`: Individual payslip calculation lines per employee.

### Migration 6 & 7: `20261009000006_recruitment_module.sql` & `20261009000007_phase7_enhancements.sql`
27. `job_postings`: Published job vacancies, openings, and requirements.
28. `job_applications`: Candidate profiles, resumes, and pipeline stages.
29. `interviews`: Scheduled interviews with ratings and evaluation scorecards.
30. `job_offers`: Formal employment offers, proposed compensation, and status.
- Transactional RPC: `public.handoff_candidate_to_employee()`.

### Migration 8: `20261009000008_phase8_operations_and_talent.sql` (Operations & Assets)
31. `onboarding_checklist_templates`: Standard task templates.
32. `onboarding_cases`: Employee onboarding instances.
33. `onboarding_tasks`: Individual checklist items.
34. `offboarding_cases`: Employee exit instances.
35. `offboarding_clearance_items`: Department clearance checkpoints (IT, Finance, HR).
36. `performance_cycles`: Appraisal cycles.
37. `performance_goals`: Individual performance targets.
38. `performance_reviews`: Formal 1.0–5.0 rating appraisals.
39. `employee_tasks`: Operational task assignments.
40. `task_activity_log`: Immutable task change log.
41. `assets`: IT hardware inventory with serial number and condition.
42. `asset_assignments`: Device assignments to employees.
43. `asset_maintenance`: Hardware service and repair logs.
44. `documents`: Employee credentials, contracts, and certificates.
45. `announcements`: Institutional notice board.
46. `announcement_reads`: Read receipts tracking.
47. `shared_approvals`: Multi-level approval requests.

## 3. Referential Integrity & Foreign Key Safeguards

- Every tenant-scoped entity links to `organizations(id)` with `ON DELETE RESTRICT` (preventing accidental tenant deletion while dependent records exist).
- Cross-Organization triggers prevent cross-tenant data corruption:
  - `enforce_employee_org_boundary`: Rejects an employee insert/update if the assigned `branch_id`, `department_id`, or `designation_id` belongs to a different organization.
  - `enforce_department_branch_org_boundary`: Rejects department assignment if the linked `branch_id` does not match the department's `organization_id`.
